# Freedom TradeNet market-data integration

## Scope

This integration adds read-only Freedom TradeNet quote, news, and daily-history proxy actions. The authenticated q WebSocket snapshot is the primary quote source. The matching Freedom REST quote is requested only if q fails; Yahoo is requested only if both Freedom quote paths fail, followed by Finnhub/Twelve Data. Company news tries Freedom first and falls back to the existing Finnhub news endpoint. Existing fundamentals, earnings, and analyst-target sections are unchanged.

## Required Cloudflare Worker secrets

Configure these in the Worker environment (never in Vite/browser variables):

- `FREEDOM_PUBLIC_KEY`
- `FREEDOM_PRIVATE_KEY`
- `FREEDOM_LOGIN` and `FREEDOM_PASSWORD` (required only for the authenticated WebSocket diagnostic; these must be the broker's login/password, not the API-key pair)

The Worker obtains authenticated WebSocket SIDs through the existing `PORTFOLIO_STATE_DO` Durable Object. It caches one production SID in that object's memory for 30 minutes and coalesces concurrent quote, portfolio, markets, and orders requests into one `authByLogin` request. The SID is never written to Durable Object storage, KV, logs, or browser responses. A WebSocket authentication rejection (HTTP 401/403, explicit demo session, or server auth/session error) invalidates only the matching cached SID.

TradeNet login rate limits are handled centrally. An application-level `{ errMsg, code: 429 }` or HTTP 429 starts an in-memory cooldown with exponential backoff (60 seconds initially, capped at 15 minutes); requests during the cooldown do not call `authByLogin` again. The cooldown and SID cache are intentionally memory-only and recover after Durable Object restart. The browser quote provider still falls back to the signed REST quote action when the authenticated WebSocket path is rate-limited or otherwise unavailable.

The Worker still requires the existing `GATEWAY_SECRET` for all app requests. After adding secrets, use the existing read-only `freedom-test` action to confirm TradeNet authentication. For failed `authByLogin` responses, diagnostics expose only the provider's bounded, sanitized `errMsg` and safe `code`/`errorCode` value (if present); credentials, email addresses, phone numbers, session IDs, and challenge tokens are never returned. A `{ errMsg, code }` response is an API-level login failure, not a WebSocket quote event failure. The Worker continues to require `success === true`, `logged === true`, a valid SID, and `real === true` before opening the socket.

## Authenticated WebSocket active-orders snapshots

The Worker exposes `?action=freedom-orders-stream` as an administrator-only, read-only active-orders snapshot action. It requires the Worker secrets `FREEDOM_LOGIN` and `FREEDOM_PASSWORD`, obtains a short-lived TradeNet SID, connects to `wss://wss.tradernet.com/` through Cloudflare's fetch-based WebSocket upgrade, and sends the read-only `orders` subscription. The SID is not persisted or returned. Once both `userData` and `orders` events arrive in a production session, the Worker returns the sanitized order list in the same envelope shape consumed by `normalizeFreedomActiveOrders`; the diagnostic metadata includes only the first ten order rows with order IDs omitted. The Worker extracts the documented nested `trade` array into a separate `data.trades.trade` collection, alongside `data.orders.order`. Each fill contains only its TradeNet trade ID, parent order ID, instrument, normalized parent-order side, currency, execution date, price, quantity, value, profit, accrued coupon interest, contract coefficient, and initial margin. Account identifiers, login names, credentials, arbitrary payload fields, and the SID are never returned. The frontend normalizes these rows into `FreedomExecutedTrade`, merges them by TradeNet trade ID, preserves locally calculated fee allocations, persists the merged broker history, and publishes the existing `broker:executed-trades` event so FIFO/Closed History consumers receive the fills. Buy-on-margin is normalized as BUY, Sell as SELL, and Sell Short remains distinct as SELL_SHORT rather than being misclassified as a closing sale. The historical `freedom-trades` REST endpoint remains the complete-history baseline, backfill, and reconciliation source; this one-shot current-period orders snapshot does not claim to provide a permanent push connection for fills arriving after the snapshot closes. The app requests one short-lived WebSocket snapshot during initial authenticated load and reuses its completed result for subsequent refreshes in that page session, rather than keeping a permanent browser socket open or reopening the one-shot endpoint every 60 seconds. The REST `freedom-orders` action is requested at most once if the initial WebSocket snapshot fails; that completed fallback is reused for later refreshes. This is a request-driven snapshot integration, not a continuous push stream. The active-order allowlist contains order ID (for internal order identity), instrument, operation, type, limit price, original quantity, remaining quantity, and status. The socket is closed after both events arrive or after an eight-second observation window. The separate administrator Market Depth stream below does not add depth to this endpoint or expose order-placement commands.

## Public US-equities market status

The app uses `?action=freedom-market-status` for a compact, read-only market indicator in both administrator and guest workspaces. The Worker authenticates the short-lived production TradeNet session, subscribes to `markets`, then returns only one US-equities state. It prefers the combined `FIX` market entry when present; if that entry is missing or unrecognized, it falls back to Nasdaq, then NYSE. No full market list, schedules, nested event data, account data, session identifiers, credentials, or SID are returned. The endpoint is guest-accessible because exchange status is public, while the raw `freedom-event-stream` diagnostic remains administrator-only.

The market event uses `n` (market name), `n2` (abbreviation/code), and `s` (current status); other schedule fields are intentionally omitted from the compact UI. Provider codes map to four UI phases: `PREV` / `PRE` / `PREPRE` → `PREMARKET`, `OPEN` / `REGULAR` → `MARKET`, `POST` / `POSTPOST` → `POSTMARKET`, and `CLOSE` / `CLOSED` → `CLOSED`. The shared UI reconciles this provider phase with the app's New York US-equity calendar; when the phases disagree, the calendar determines the displayed phase so a provider `CLOSED` value cannot hide premarket, regular, or postmarket hours. The same effective phase drives the badge and its countdown. Unknown provider status values are rejected rather than shown as raw codes. The app refreshes this one-line status every five minutes, when the document becomes visible again, and after an authenticated user change. Both admin and guest headers use the same public endpoint; the UI labels them separately.

The `markets` event is the exchange trading-status source, not a quote-price feed. The separate `sessions` / `session` API concerns user security sessions (authorization/session management), not exchange trading hours, so it is deliberately not subscribed to or treated as a market calendar. Per-symbol last-trade quotes use the separately verified q WebSocket snapshot below; `getStockQuotesJson` / `freedom-quote` remains only as the corresponding REST fallback when q cannot provide a valid quote.

## Administrator live Market Depth

The dashboard offers an administrator-only, read-only Market Depth modal from margin-position cards and administrator Balance holding rows; guest holding cards do not expose this action. Clicking the button requests a short-lived, single-use Worker ticket bound to the authenticated admin account and normalized ticker (the Worker appends `.US` if no exchange suffix is supplied), then opens a browser WebSocket. The Worker keeps the TradeNet SID server-side, authenticates to the production socket, and sends the `["orderBook", ["AAPL.US"]]` subscription. `orderBook` is the subscription command; `b` is the response event. No documented depth-count parameter is sent, so TradeNet and the account entitlement determine how many levels are available. The socket remains live while the modal is open and receives incremental `ins`, `upd`, and `del` updates.

The `b` event payload may wrap one or more per-ticker update blocks in a `dom` array; the Worker unwraps that envelope before applying deltas. The `k` field is the position in the combined order book (ask and bid rows share the same index space), and `s` identifies each row as bid (`B`) or ask (`S`). Deltas are applied in the documented `del`, `ins`, then `upd` order. The accumulator accepts a deletion as a global position (`k`) even when the provider omits the row's side/price/quantity, and validates `s` when it is present. The Worker validates ticker and sequence metadata, and rejects gaps or inconsistent positions rather than publishing a silently corrupted book. On a position/side conflict, the accumulator reports a bounded rolling history of recent `del`/`ins`/`upd` row positions to identify which earlier delta first shifted the book. It caps accumulated data at 1,000 levels per side as a local safety bound; this is not a request for or guarantee of 1,000 provider levels. The UI combines quantities at identical prices and shows best bid/ask, spread, midpoint, visible-size imbalance, a proportional-liquidity ladder for the five best-priced levels per side, and an expandable detailed table of the levels received. Level counts indicate what TradeNet actually returned. The browser never receives raw broker fields, account identifiers, the SID, or credentials. Closing the modal closes the browser socket and its associated upstream TradeNet connection. The Worker also enforces idle and maximum session lifetimes and a per-account session limit. Guests cannot access the ticket or socket endpoint; no trading or order-placement action is enabled.

## Authenticated live quote WebSocket probe

The read-only `?action=freedom-quote-stream&symbol=GOOGL.US` probe remains available for one-shot diagnostics and initial-recovery checks. It uses the raw `wss://wss.tradernet.com/` protocol and the existing short-lived production SID. It is available to authenticated administrators and guests because it returns only public instrument quote data; the Worker never exposes the SID or broker account information. Guest tickers are derived exclusively from the server-filtered guest tranche projection, not the administrator's portfolio. It sends `["quotes", ["GOOGL.US"]]`, waits for the `q` response plus production `userData`, and verifies the returned ticker. The parser accepts both the raw `q` event's direct single-quote object (observed in production) and array/wrapper forms. It uses `ltp` as the documented last-trade price, `bbp`/`bap` as best bid/ask, `pp` as previous close, and returns only an allowlist of quote fields (change, volume, timestamp and instrument/currency metadata). If supplied by TradeNet, the allowlist also includes `UTCOffset` and `acc_srv_tm` so the client can assess the timezone and server-observation time without guessing. It closes the socket after the first matching quote or the eight-second observation timeout. This endpoint is not the persistent browser stream; see “Persistent TradeNet q quote stream” above. The app prefers the persistent q connection. The one-shot endpoint is used only for initial recovery when the persistent connection cannot be established; a successful persistent q stream suppresses scheduled quote REST requests. If both persistent and one-shot q requests fail, the app tries the signed Freedom REST quote, then Yahoo, followed by Finnhub/Twelve Data. The raw protocol and event names follow the [TradeNet WebSocket documentation](https://tradernet.am/tradernet-api/websocket?site_lang=en).

When the requested ticker is not found or the quote wrapper is unrecognized, the Worker includes a redacted `diagnostics.eventSummary` with the quote container path/type, row count, allowlisted field names and value types, and up to ten public ticker identifiers. It never includes quote prices or the raw quote payload in an error response. The existing `freedom-quote` REST call and Yahoo/Finnhub/Twelve Data providers remain available only as sequential failure fallbacks. Market Depth is a separate administrator-only captured view and is not merged into the persistent quote stream.


## Persistent TradeNet q quote stream

The app uses a persistent browser-visible WebSocket for ongoing q quote updates. The browser first makes an authenticated HTTPS request to `?action=freedom-quote-stream-ticket&symbols=GOOGL.US,AAPL.US`. After verifying the current account session and role, the Worker asks the `portfolio_state` Durable Object to issue a cryptographically random, 60-second, single-use ticket bound to the account ID, role, and normalized ticker set. Only a hash of the ticket is stored, and ticket consumption is atomic.

The browser then opens `wss://trading-proxy.armenavetisyan-sa.workers.dev/?action=freedom-quote-socket&ticket=...`. The browser-visible socket carries only the short-lived one-use ticket; it never carries the Gateway Secret, TradeNet login/password, or TradeNet SID. The Worker forwards the WebSocket upgrade to the same Durable Object. The Durable Object consumes the ticket and attaches the browser socket to its hibernatable quote-client group.

The Durable Object obtains the production SID through its existing server-side session broker and maintains an upstream connection to `wss://wss.tradernet.com/`, subscribing to `["quotes", symbols]`. It shares that upstream q subscription across authenticated browser clients in the same portfolio workspace, adds newly requested symbols when needed, and routes each sanitized q row only to browser clients that requested that symbol. When the active browser ticker set shrinks, the Durable Object rebuilds the upstream subscription with only the remaining symbols (the implementation does not rely on an undocumented unsubscribe packet) and evicts cached quotes for removed symbols. The q allowlist includes last price, previous close, change, bid/ask, volume, trade time, exchange offset and server observation time when present; account/login/owner fields and the SID are never forwarded. The most recently observed quote is retained in Durable Object memory and sent to a new browser client after it receives the ready message.

The browser runtime keeps the client WebSocket open, sends a heartbeat every 20 seconds, requires a pong within 45 seconds, and reconnects with a fresh single-use ticket using bounded backoff after a close/error or a missed pong. When the upstream TradeNet connection closes or errors, the Durable Object marks clients as reconnecting and establishes the upstream subscription again when the next client heartbeat arrives. Account or ticker-set changes replace the browser subscription; logout stops it. When the last browser client disconnects, the Durable Object closes the upstream TradeNet socket and clears its in-memory quote cache.

Each q update is normalized and written through the canonical portfolio store. Every newly received WebSocket event overwrites the matching ticker's local current price and complete quote metadata; the browser receive time plus monotonic event sequence determine arrival order. A regressing/repeated provider `ltt` timestamp affects the quote's freshness label but does not block a later-received q event from updating local state. Out-of-order one-shot HTTP/provider responses retain their request-sequence and source-timestamp safeguards. The canonical store persists the change and immediately re-renders the portfolio. The app does not need a scheduled REST request for each quote change. A valid persistent stream suppresses the one-shot q snapshot and corresponding Freedom/Yahoo quote REST requests. If the persistent socket cannot initially be established, the app attempts the existing one-shot q snapshot and then the existing Freedom/Yahoo/Finnhub/Twelve Data fallback chain. Historical candles, trades and cashflows remain REST-backed.

The browser DevTools Network panel should now show a persistent WebSocket request named `?action=freedom-quote-socket&ticket=...` with status `101 Switching Protocols`. The actual upstream `wss.tradernet.com` connection is server-to-server inside Cloudflare and will not appear in the browser's Network panel. Prices change only when TradeNet sends a new q event for a subscribed symbol; this is event-driven, not a fixed one-second timer.

Guests use the same public q stream, but their requested ticker set is derived only from their own server-filtered guest portfolio projection. The Worker continues to deny guest access to account-wide portfolio, orders, fills, cashflows and private portfolio events.

## Portfolio WebSocket versus REST reconciliation

The administrator-only `?action=freedom-portfolio-snapshot` action obtains one authenticated production `portfolio` event, requires `loaded === true`, and returns only the same normalized USD account and position fields exposed by the existing `freedom-positions` REST action. Non-USD rows, broker IDs unrelated to the app's existing position contract, timestamps, session identifiers, credentials, and raw payload fields are omitted. The application now uses this authenticated WebSocket snapshot as the primary source for account balances and positions. The existing `freedom-positions` REST action (`getPositionJson`) is requested at most once as fallback when the initial socket is unavailable, times out, returns an incomplete/unloaded snapshot, or fails validation; the completed snapshot or fallback result is reused for later refreshes in the same authenticated page session. Both sources pass through the same `normalizeFreedomPortfolio` contract. The admin Settings reconciliation check can still request both sources independently and compare field-level values with a 0.01 numeric tolerance; that comparison is read-only and never writes to the portfolio store or changes saved holdings.

## Persistent administrator portfolio and orders streams

The administrator app opens a dedicated browser WebSocket through `?action=freedom-account-socket`. It first requests a short-lived, single-use ticket with `?action=freedom-account-stream-ticket`; the Worker requires an authenticated administrator session and binds the ticket to that account ID. The ticket is consumed by `PortfolioStateDO` during the WebSocket upgrade. The browser never receives the TradeNet SID, broker password, or an unrestricted upstream URL.

The Durable Object opens one authenticated production connection to `wss://wss.tradernet.com/` and subscribes with the documented messages `["portfolio"]` and `["orders"]`. It waits for the `userData` production-session confirmation before forwarding any account payload. If data arrives before the confirmation, it is held in a small in-memory queue and processed only after production mode is confirmed. Only the normalized USD portfolio fields and allowlisted order/fill fields are forwarded. Guest accounts cannot mint these tickets or use this socket. The existing quote socket remains separate, as do public guest quote subscriptions.

Portfolio events are passed through the existing `normalizeFreedomPortfolio` contract and update the current broker portfolio state. Order events are sanitized and accumulated by broker order ID so order status changes can be applied without losing the rest of the current order list. Embedded fills are deduplicated by TradeNet trade ID, normalized through `normalizeFreedomOrderFills`, and merged into broker execution history while preserving app-owned fee allocations. The server-side order accumulator and latest event snapshots are in memory only and are rebuilt from the initial subscription response after a reconnect.

The one-shot `freedom-portfolio-snapshot` and `freedom-orders-stream` actions remain the initial hydration and fallback/reconciliation path when the persistent socket cannot be established. Once live events arrive, the app applies those events directly; it does not run recurring REST calls as a backup for portfolio or active-order updates. The `freedom-trades` REST endpoint remains the historical execution baseline/backfill/reconciliation source, and cashflows, news, and historical price data remain REST. There is no separate TradeNet HTTP webhook endpoint used here: these are authenticated WebSocket event subscriptions.

Cloudflare note: the browser-facing Durable Object WebSocket can use the Durable Objects WebSocket Hibernation API, but the outbound TradeNet client socket cannot hibernate. It therefore keeps the account Durable Object active while the broker connection remains open. Keep this in mind when evaluating connection lifetime and Cloudflare usage. The implementation closes the account upstream when the last administrator account-stream client disconnects. Market Depth uses a separate modal-scoped upstream socket documented above.

## Read-only actions

- `freedom-trades` retrieves the full TradeNet execution history for FIFO matching when no local closed-trade cursor exists. On a warm cache, the Worker accepts only a validated `fromDate=YYYY-MM-DD` cursor and translates it to `getTradesHistory` `beginDate` at midnight, `endDate` at the current time, and `sort: 0`. The client merges the returned period into persisted executions so older opening buys remain available for FIFO matching. Without a cursor, the Worker requests `sort: 0` and omits `max`; the latest-first `sort: 1` mode defaults to 100 executions and can omit older opening buys.
- `freedom-cashflows` accepts the same validated `fromDate` cursor and translates it to the inclusive TradeNet `getUserCashFlows` filter `date eqormore YYYY-MM-DD`, sorted oldest-first. Cached cashflows are retained and merged with the returned period.
- The first sync after this incremental-sync rollout performs a one-time complete trades and cashflow baseline for each app account. Baseline markers are written only after the complete source rows have been persisted locally. This avoids treating a pre-feature partial cache as complete; subsequent refreshes use the latest closed-trade date.

- `freedom-quote`: requests a quote for one symbol.
- `freedom-news`: requests company news for one symbol.
- `freedom-history`: requests daily historical data for one symbol.

The browser cannot supply an arbitrary TradeNet command. The Worker chooses from a fixed allowlist and signs requests server-side. No order-placement command is exposed.

The quote action uses TradeNet's `getStockQuotesJson` command with a `tickers` array (a one-element array for a single-symbol request). For the API-key v2 route, the command is in the URL (`/api/getStockQuotesJson`), and the JSON body contains only the command parameters (for example, `{"tickers":["GOOGL.US"]}`), not the legacy `{cmd, params}` envelope. The Worker signs the exact serialized body followed by the current Unix timestamp, as described by the [TradeNet API-key documentation](https://tradernet.global/tradernet-api/auth-api?site_lang=en). TradeNet returns quote records in the `q` array (for example, `{"q":[{"c":"GOOGL.US","ltp":279.84}]}`). The response normalizer unwraps this envelope, including when nested under `data`, and reads `ltp` (last price), `pp` (previous close), `chg` (absolute change), and `pcp` (percent change). See the [TradeNet quote API documentation](https://fbis.tradernet.ae/tradernet-api/quotes-get?site_lang=en).

Symbols without an explicit exchange suffix are mapped to `.US`; symbols already containing a dot are passed through. Review this mapping for non-US instruments before relying on it.

## Validation status and limitations

The Worker regression test verifies the API-key v2 request URL, parameter-only JSON body, and HMAC signature; the frontend unit test covers the documented quote fields. The Worker deployment workflow also watches the shared TradeNet adapter file so changes to the imported signing/request helper are deployed. A successful response against the configured, authorized Freedom Broker Armenia account is still required to validate account entitlement and live symbol coverage. If both the authenticated q snapshot and signed Freedom REST quote fail, Yahoo is tried next; Finnhub and Twelve Data are the final sequential fallbacks. If Freedom news is unavailable or returns no recognized stories, the existing Finnhub news path is used.

The target-price, analyst-consensus, detailed fundamentals, and earnings-estimate integrations are intentionally unchanged; this change does not claim those fields are available through Tradernet.


## Balance snapshot synchronization

The Balance desk restores the last persisted portfolio snapshot immediately and keeps it visible while the authenticated portfolio WebSocket snapshot runs. The read-only `freedom-positions` REST action is used only as the one-time recovery path if that snapshot fails. The account request is always a full snapshot: it does not accept or send a date cursor, begin/end date, or other history filter. A successful TradeNet response is normalized and committed through the canonical portfolio store, which persists the account balance, classified holdings, broker snapshot and derived cash holdings locally and through the existing cloud-state sync path. Refresh failures mark the broker snapshot stale without clearing the last good values.

The Balance page does not wait for the separate execution-history request before rendering cached account holdings. It restores and merges the saved execution history with the current portfolio-store copy so the Active Tranches view does not lose older opening purchases if one source is incomplete. Background account/trade refresh activity is shown beside the Balance heading; a blocking loading view is used only when an administrator has no cached broker account snapshot yet. Guest Balance remains scoped to the guest portfolio projection and does not request account-wide broker data.

## Role-specific mandatory synchronization

Each signed-in role has its own saved refresh cadence (15, 30, or 60 seconds); automatic sync cannot be disabled. The same selected cadence now triggers the complete role-scoped refresh rather than running quotes and account data on separate timers.

- **Admin:** refresh quotes and the shared portfolio cloud snapshot; refresh broker balances/positions, executions and active orders when the authenticated account stream is not healthy; merge and sync Closed History and cashflows; checkpoint the portfolio after history allocation changes.
- **Guest:** fetch only that guest's authenticated assigned-holdings snapshot and LOTS ledger, then refresh quotes for the latest assigned tickers. Guest sessions never request administrator broker balances, orders, trades or shared private history.
- **Both roles:** the Settings **Sync portfolio** action remains available for an immediate full role-specific sync. Returning to a visible tab also triggers a full refresh. Hidden tabs pause scheduled network work and catch up when visible again.

Legacy saved `Off` values are migrated to the account role's safe default (admin: 60 seconds; guest: 15 seconds). Admin and guest cadence preferences remain stored separately on the device.

## Account stream health and REST recovery policy

The administrator's persistent account stream is considered healthy only after the browser socket has completed its ready handshake, the heartbeat pong watchdog remains current, and valid portfolio **and** orders events have both been applied to the active account session. Once healthy, scheduled refreshes do not request recurring `freedom-positions`, `freedom-orders`, or `freedom-trades` REST data. The live orders channel continues to feed active orders and embedded fills.

The authenticated startup sequence still requests the complete historical `freedom-trades` baseline once. It is retained as the source for initial history hydration, incremental gap recovery, and explicit Manual Sync/reconciliation. When a previously connected account stream disconnects or reports an upstream reconnect, the app allows one incremental REST catch-up for that outage, even when the socket reconnects before the next scheduler tick. Repeated reconnect notifications during the same outage do not trigger repeated REST work. A later, distinct disconnect opens a new one-time recovery window.

Account balances/positions and active orders continue to use their existing one-shot WebSocket snapshot contracts for startup/recovery, with REST fallback only when the corresponding snapshot is unavailable. Per-channel event revisions prevent an in-flight one-shot snapshot from overwriting a newer live push. Manual Sync remains explicit; independent cashflow, news, historical market data, and research endpoints are not covered by the account stream and remain on their existing request paths.

The browser sends an account-stream heartbeat every 15 seconds and expects a pong within 40 seconds. A missing pong closes the half-open browser socket; a reported stream error closes the socket so bounded reconnect can request a fresh one-use ticket. Stream health is reset on account-session changes and requires both private data channels to resume before scheduled REST suppression is re-enabled.
