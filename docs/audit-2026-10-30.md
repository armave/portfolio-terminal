## Findings and changes

### Stocktwits sentiment

The stream renderer displayed bearish labels but included bearish messages in the visible feed. The visible-message selector now removes bearish messages after reply filtering and before applying the ten-message limit. Sentiment resolution uses the same precedence as the badge renderer: primary `sentiment.basic`, then `entities.sentiment.basic`. Unknown and neutral messages remain visible; a contradictory secondary field does not override the sentiment the UI actually displays.

Regression coverage includes both sentiment payload shapes, casing/whitespace, unknown values, conflicting source fields, reply filtering, and the visible-message limit.

### Margin tranche summary

The single-position summary previously concatenated every entry tranche into one long text string. It now previews three entries, reveals the remaining entries behind an accessible `Show N more` / `Show less` control, and reuses the existing `.expandable-motion` transition. The control declares its expanded state and controlled region; the shared stylesheet already includes reduced-motion handling.

A pure preview helper and focused tests cover the three-entry boundary and ensure the stored tranche array is not mutated. Financial quantities, prices, cost basis, and tranche ordering are unchanged.

### Closed History upload lifecycle

Saved cashflow rows are recalculated automatically by the same routine used for workbook imports. That routine also toggled the manual upload control's loading/disabled state, making the file-import label appear to change during background history work. The progress state is now gated to the file-upload path; background recalculation leaves the control untouched. Background recalculation errors are logged rather than being silently discarded.

The picker previously advertised both `.xlsx` and `.xls`, while the built-in reader only parses XLSX ZIP/XML workbooks and the importer already rejected `.xls`. The picker and validation now agree on `.xlsx` only. Tests cover the progress-state contract and supported extensions.

- Existing architecture notes continue to identify follow-up work around boundary types, legacy runtime orchestration, and the remaining consolidation step. This pass addresses the three reported defects and documents, rather than silently expanding, the higher-risk work.
