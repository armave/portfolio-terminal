## Audit summary

The current application is not a legacy Vanilla DOM application. It uses one Preact root, TypeScript components, a canonical portfolio store, typed UI and broker event channels, domain calculation modules, and dedicated services for provider access, storage, and cloud synchronization. Root `app.ts`, `src/App.tsx`, `worker.js`, and `state-store.js` remain active architecture boundaries; none were removed based on size or age.

No new defect was demonstrated in those paths, so their behavior was left unchanged.

## Findings and changes

### 1. Trades recovery was not actionable

**Finding:** when the TradeNet executions request failed, the Trades desk showed a “Please retry” message but had no retry control. When saved executions were available, the failure state was not visible, so historical rows could appear current.

**Changes:**
- Add an explicit retry action that reissues the existing typed broker request; the current App listener already owns the request and its in-flight deduplication.
- Keep existing saved rows visible while a retry is in progress, and expose refresh progress with an accessible status message.
- On failure with saved rows, show that the visible history may be stale and provide a retry action.
- On failure without saved rows, provide a retry action in the empty/error state.
- Clear the refresh state on both success and failure.

No TradeNet endpoint, broker behavior, portfolio mutation, or accounting calculation is changed.

### 2. Closed History table usability

**Changes:**
- Add a table caption and explicit column-header scopes for screen-reader navigation.
- Give the horizontally scrollable table a readable minimum width on small screens and make its scroll region keyboard-focusable with a visible focus outline.
- Preserve all existing columns, pagination, data ordering, and calculations.

### 3. Localization coverage

Added Russian translations for the new stale-history warning, retry label, refresh status, retrying status, and accessible table caption. Added unit coverage to verify the new strings are translated.

### 4. Outdated repository conventions

The previous `CONVENTIONS.md` still described Vanilla DOM rendering, an obsolete `storage.js` path, and the former architecture. Rewrote it to reflect the actual Preact/TypeScript architecture, canonical portfolio state, typed event channels, service/domain boundaries, security posture, accessibility requirements, PR/rebase expectations, and the current CI validation commands.
