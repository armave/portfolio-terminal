# Refactoring & Code Conventions

These conventions describe the current Preact, TypeScript, and Cloudflare Worker architecture.

1. **Language:** Keep source comments, documentation, commit messages, and developer-facing explanations in English. User-facing application copy must use the localization system in `src/services/i18n.ts` when it is part of the supported interface.

2. **UI ownership and state:** Preact components own the UI they render. `src/store/portfolioStore.ts` is the canonical owner of portfolio state; `positions` is authoritative and `holdings` is a compatibility projection. Components should subscribe through the store hooks and issue typed actions/events. Do not maintain redundant prop/state mirrors or mutate sibling-owned DOM. Use refs and effects for browser APIs that act on an element owned by the component (focus, measurement, scrolling, and similar lifecycle work).

3. **Application and service boundaries:** Keep application orchestration in `app.ts` and `src/App.tsx`, provider/network access in `src/services/`, and presentation in `src/components/`. Route market-data proxy requests through the API service (`proxyFetch(action, params, options)`) so authentication headers, request coalescing, error handling, and session-aware caching remain centralized. Components and domain modules must not call provider endpoints directly.

4. **Domain logic:** Keep financial and other business calculations deterministic and independent of UI, storage, and network APIs. Reuse pure functions from `src/domain/`; do not duplicate commission, interest, rollover, FIFO, valuation, fee-allocation, or risk formulas in components or runtime orchestration. Changes to financial semantics require focused regression tests and an explicit explanation of the compatibility impact.

5. **Persistence and compatibility:** Use `src/services/storage.ts` for portfolio persistence, backups, broker assumptions, and device credential storage. Keep cloud revisions and device-only navigation preferences within their existing owning service/store boundaries; they are not portfolio state and must not contain credentials. Preserve legacy snapshot compatibility, encrypted cloud-history behavior, revision checks, and rollback guarantees. Never silently replace missing or malformed data with an empty portfolio when doing so could discard recoverable user data.

6. **Typed communication:** Use the typed in-process channels in `src/ui/uiEventBus.ts` and `src/services/brokerEventBus.ts` for component/runtime requests and broker updates. Add or change event payloads in the channel's type map and cover delivery, multiple subscribers, and unsubscribe behavior in tests. Do not reintroduce ad-hoc `window` custom events or global mutable caches.

7. **Worker and security boundaries:** Keep Worker routes and Durable Object storage in `worker.js` and `state-store.js`. Validate method, authentication, action, input shape, and payload bounds at the server boundary. CORS/origin allowlisting is defense in depth, not authentication. Never expose gateway credentials, broker session identifiers, raw sensitive provider payloads, or secrets to browser logs or UI. Client-side changes should not weaken server-enforced authorization.

8. **UI and accessibility:** Use semantic Preact markup and the existing Tailwind/CSS design system. Keep tables readable on desktop and keyboard-scrollable on narrow screens; provide accessible names, column headers, visible focus, useful loading/error/empty states, and touch-sized actions. Respect reduced-motion preferences. Keep English/Russian static copy in the localization dictionary and test important dynamic translations. For rarely used desks and modal-only UI, use `lazy` imports with a lightweight `Suspense` fallback; do not add a dynamic import for a module that is already statically imported in the same entry graph.

9. **Scope and cleanup:** Inspect all connected callers, producers, consumers, tests, styles, and documentation before deleting or replacing a legacy path. Remove code only after proving it is unused or a no-op. Do not delete active runtime/Worker files because they are large or older, and do not add a framework or dependency without a concrete need. Never leave placeholders, truncated code, unused compatibility branches, or incomplete implementations.

10. **Branch integration:** Start frontend, UI, client-side, and related documentation changes from the latest `dev` and submit them through a focused pull request targeting `dev`. Review branch divergence before rebasing or cherry-picking; replay only changes whose intent is still valid, resolve conflicts semantically, and do not force-update unrelated in-flight branches. Preserve production-only commits on `main`; do not replace `main` with `dev` or rewrite its ancestry during client delivery. Publish Worker/server-only changes through the designated direct-to-`main` deployment workflow, and separate mixed client/server delivery so the backward-compatible server change is deployed and verified first.

11. **Validation:** Run the repository's full merge gate on the final change set:
    - `npm ci`
    - `npm run typecheck`
    - `npm run test:coverage` (the complete Vitest suite with V8 coverage; avoid running `npm test` immediately before it for the same candidate)
    - `npm run test:financial` when financial, persistence, backup/reconciliation, or Worker authorization paths change
    - `npm run validate:dead-code`
    - `npm run audit:dependencies`
    - `npm run audit:production`
    - `npm run build`

    Use `npm run ci:local` to reproduce the complete GitHub Actions validation locally, including the production browser smoke test, desktop/mobile performance baseline, and Operations browser journey. It starts with `npm ci`; pass `-- --skip-install` only when the current lockfile dependencies are already installed.

    The checked-in devcontainer provisions Node.js 22, Playwright/Chromium, and the Git pre-push hook. In an existing checkout, run `npm ci` and then `npm run setup:browser-tests`, install Chromium with `node node_modules/playwright/cli.js install chromium`, and activate the hook with `npm run setup:git-hooks`. The hook runs the same local CI suite while reusing installed dependencies.

    Inspect the final diff for unintended financial, persisted-data, broker, security, and deployment changes. Report unavailable checks honestly; never claim a test or build passed without evidence. Resolve failures at their source rather than weakening assertions or skipping checks.
12. **Numeric literal formatting:** For readable JavaScript/TypeScript numeric literals of 1,000 or greater, use `_` separators in groups of three digits from the right (for example, `1_000`, `60_000`, and `1_800_000_000_000`). Leave smaller values unseparated. Use descriptive unit constants such as `DAY_MS` when a literal represents a reusable unit conversion. Never insert numeric separators into strings, JSON, dates, API payloads, persisted formats, identifiers, HTML input values, or user-facing formatted numbers; those representations must follow their external or localized format. Do not mechanically rewrite existing literals solely to add separators.

## CI, security, and deployment gates

- `.github/workflows/ci.yml` is the single PR validation entry point. Its change detector skips application jobs only for documentation-only changes, skips build/browser jobs for workflow-only changes except edits to the primary `ci.yml` entry workflow (which run the build and browser journeys end-to-end), and defaults unknown or incomplete change metadata to full validation. The quality job runs the complete Vitest suite once with `npm run test:coverage`; the separately named coverage job consumes that exact report artifact and rechecks the unchanged aggregate floors rather than rerunning tests. Static checks and the production build remain independent; browser journeys consume the exact production artifact produced by that run.
- `.github/workflows/operations-browser.yml` is reusable by PR CI and remains manually runnable. It does not repeat unit tests, typecheck, dead-code validation, dependency audits, or the production build when called by PR CI.
- `.github/workflows/financial-regression.yml` keeps the focused transaction, financial-domain, persistence, backup/reconciliation, and Worker/authentication subset available through manual dispatch. Automatic PR/push validation runs the complete Vitest suite, which already includes those tests; do not execute the same subset a second time for every commit.
- `vitest.config.ts` collects V8 coverage for the financial domain, portfolio store, Worker and Durable Object. Aggregate floors are lines 80%, statements 80%, functions 85%, and branches 70%; these floors are anchored to the measured baseline in `docs/ci/coverage-baseline-2026-11-17.md` and must not be lowered to conceal regressions.
- `.oxlintrc.json` enables a small correctness-focused Oxlint baseline for production JavaScript/TypeScript. Vitest files remain governed by Vitest assertions and TypeScript's `noUnusedLocals`/`noUnusedParameters`; expand lint rules incrementally only after checking the existing codebase.
- `.github/workflows/security.yml` always runs a blocking Gitleaks scan over commits introduced by each PR/push. CodeQL runs when source/test code changes; actionlint and zizmor run when workflow or CI-infrastructure files change. Manual and scheduled runs execute the complete security validation. A separate scheduled/manual full-history Gitleaks audit is advisory so legacy findings remain visible without hiding new leaks. Treat new-commit findings as merge blockers; do not add broad secret-scan suppressions.
- `.github/dependabot.yml` keeps npm and GitHub Actions dependencies on a weekly update cadence. Review major-version updates separately; do not automatically accept breaking changes. Version-update PRs target `dev` for both ecosystems; Dependabot security-update PRs continue to target the repository default branch (`main`). The weekly security workflow also runs full and production-only `npm audit` checks.
- `.nvmrc` is the shared Node.js version source for CI; `package.json` and `package-lock.json` declare the supported Node.js 22.x and npm 10.x ranges. Keep the README and development environment aligned with that contract.
- Third-party GitHub Actions must be pinned to immutable commit SHAs and annotated with the corresponding release version. Keep those SHAs current through Dependabot.
- Pages deployment is the final job in `.github/workflows/ci.yml` for pushes and manual runs on `main`. It waits for quality, coverage, production build, and browser journeys in the same workflow run, validates the commit/run provenance stamped into the artifact, then waits for a successful `Security & Workflow Validation` push run for that exact `main` SHA before publishing and performing a post-publish HTTP smoke check. Do not use a privileged `workflow_run` publisher or rebuild a different artifact. Worker deployment remains a separate `main`-only lane and must typecheck, run Worker/authentication tests and dependency audits, wait for the same exact-commit security gate before deployment, then verify its read-only versioned health endpoint reports the exact deployed SHA.
- Require the PR CI quality, production-build, browser-smoke, operations-browser, workflow-security, secret-scan, and CodeQL checks in repository branch protection. Branch-protection settings live in GitHub repository settings and are not enforceable by workflow YAML alone.
- `npm run ci:local` reproduces project typecheck, Vitest, build, browser, dead-code, and npm-audit validation. GitHub-hosted CodeQL, Gitleaks, zizmor, and actionlint jobs remain authoritative for their respective scans.
